## 事后核对：误报变多是碎片化造成的（只描述）

[mem_dilate_frames_posthoc.py](mem_dilate_frames_posthoc.py) 在 τ=5 时按帧统计盲人行走者的误报（`mem_dilate_frames_posthoc.log`）：

| | 误报帧/km | 误报次数/km | 每次平均帧数 |
|---|---:|---:|---:|
| 记忆 | 732.5 | 38.9 | 18.8 |
| 神谕 | 375.5 | 26.4 | 14.2 |
| 召回 1.0，外扩 3 | 412.8 | 32.5 | 12.7 |
| 召回 0.8，外扩 3 | 621.4 | 43.5 | 14.3 |

- 按帧计算，召回 1.0 加外扩 3 追回了 (732.5−412.8)/(732.5−375.5) = 90%；召回 0.8 加外扩 3 追回 31%。
- 召回 0.8 时误报帧数在减少，但原本连成一片的拖影被切成更多段，所以按次数计反而变差。
- 判据按次数计，这是预先冻结的口径，结论不改。帧级数字只用来说明原因。

## 对路线的含义

在本模拟中，去拖影要有效，需要行人在**每一帧**都被删掉。逐帧独立漏检 20% 就足以抵消收益。
实际检测器加上跨帧跟踪，可以补上短暂的漏检，漏检方式未必是逐帧独立的；这一点本模拟无法回答。
要么用真实检测器和跟踪在 RGB 上直接测（需下载 41.7 GB），要么在此暂停。
