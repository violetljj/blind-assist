# RGB细结构先检测再定位：已有数据可行性

2026-10-13，EXPLORE，用户授权“试试看”。

目标：检验原融合未报警时，RGB中的竖杆/横杆是否仍可由自主候选稳定定位，并与门框、地砖/台阶线等结构区分。先验证看得见/跟得住，再决定候选级距离；本轮不直接接入报警。

数据：已消费18段1677就绪帧的RGB索引和DAV2缓存。主评价在H5/H6/H7/H8每段按就绪帧序列均匀抽6帧（共24），另电视墙/低头大厅各6帧作为无目标杆干扰样本；时间抽样在看检测结果前确定。标注者是本助手依据原RGB视觉判读，属于弱标注，不称人工真值；允许遮挡/模糊/目标不存在为NOT_EVALUABLE，不编造完整可见杆。图像端点/可见段只用于评价，候选实现与跟踪不读取标注。

候选机制：图像线段/平行边对提议，单边作为召回对照；已有相对深度中候选中心与两侧的局部前景对比；时序关联明确区分自主发现与人工初始化。保持旧ToF/尺度/融合/150px门槛不变。读出提议命中、筛选后命中、持续性、干扰候选数量与原融合未报警子集；不把候选可见率称接触检出率。评价端点距离与线覆盖共同约束，避免碰到杆一点即算命中。

预算：本轮CPU≤1200 command-wall秒（独立检测600，标注/评价/整合600），GPU0、下载0、无重训；新payload≤1GB，路径 `artifacts.local/work/thin-structure-dev-20261013/`。模型缓存缺失帧保留RGB提议并标深度UNKNOWN，不算负例；处理全部18段，不按标签跳过难场景。发生明确失败可在范围/预算内调整机制并保留原结果；获得足以决定的结果或达到预算则结束。

## 结果

**找到值得继续开发的机制：直接提取相对深度细脊，比先找RGB边缘更容易定位竖杆。** 相同22张可评价弱标注中，线段top40命中12张，深度细脊命中17张，配对救9/损4；旧融合未报警11张中命中3→9张。尚未解决稳定跟踪、物体区分和公制身体区域判定，不能称报警升级。

### 实际执行与失败保留

1. 全18段1677就绪帧：RGB LSD长度≥25px，保留最长160边，平行边配对，按长度/配对/局部深度分数取40候选；全图角点LK＋RANSAC仿射做关联。1344帧有已有DAV2缓存，其余深度UNKNOWN。原始输出59997候选。
2. 排序诊断：导出固定160边范围内全部158562提议；22张命中仍12，说明本例主要不是top40排序丢失。4方向×3×3位置配额同样12/22，不采用该排序改动。最初“长背景边挤掉杆”的猜想未得到主结果支持。
3. 只供诊断的标注中心取值：19张有深度样本中14张在中心相对两侧±6px有≥0.02全图IQR前景突出。这个结果读取标注，属于oracle诊断，不能当自动检出。
4. 根据诊断新增自主深度脊：4个法向、±4/8/12px取相对两侧均更近的响应，≥0.02 IQR；Hough线长≥25px、间隙≤8px、支持率≥0.6、方向容差15°，每帧最多40条。实现不读标注，不用人工种子或ToF证实。全1677帧输出18483候选。只执行这一组机制参数，没有扫阈值；属于本轮看结果后的Development探索。

### 决定与下一步

保留自主深度脊作为**细结构候选生成器**，优先于继续调整全图尺度/150px门槛。最有希望的后续是以这些局部候选作目标级跟踪，再沿候选估距离与身体区域；横柄保留RGB边线补充的可能。关键待证假设是：候选的公制位置能区分身体内外，而且局部跟踪不会沿背景漂移。下一次应在固定安装、已知杆距离/侧向位置及去杆对照下检查该假设。原尺度robust_replace、冻结v1/v2与手机默认保持原身份，本轮不直接接入报警。

结论限已消费18段中的助手视觉弱标注，效果评价来自4个目标片段/22张，另2张不可评价；开发诊断驱动新机制，没有独立测试集，也没有接触/安全确认。未训练、下载、推理新模型，使用已有深度缓存。
