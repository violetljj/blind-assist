# 阶段总结：头戴 ToF＋RGB 融合避障（2026-10-12～13）

单一用户、单一设备（AtomS3R 鱼眼相机＋BMI270 IMU，H3 上的 ST VL53L8CH 8×8×16 直方图 ToF，手机 SM-S9280 采集）。标签都由 Claude 只看 RGB 缩略图判读，没有逐 query 的接触真值。下面的数字都是开发或冻结检验结果，不是安全性证明。

## 1. 现行方案（冻结 v3）

- **ToF 分支**：俯角/地面/噪声联合训练的模拟模型，只取强档报警；姿态门控（俯角 > +10° 或 |横滚| > 25° 时不报）。
- **RGB 分支**：官方 DAV2-Small 相对深度，输入短边 518（手机 HTP 实测约 120 ms）。尺度依次取：ToF 区仿射拟合（未过质量合同时换成两点共识稳健拟合）→ 地面锚定（头高取低头标定，默认 1.35 m）→ 沿用上一帧。头前 HEAD/BODY 盒（横向 ±0.30 m、前方 0.30–2.0 m）内满 150 像素即报警。
- **融合**：按 query 取 ToF 强档或 RGB，2/3 帧确认（v2 起）。
- 版本：v1（10-12 冻结）、v2（加时序确认）、v3（10-13 录制前冻结，加稳健锚定）。

|---|---|---|---|---|---|

合计：**ahead 6/6、quiet 3/3、side 1/1，v1/v2/v3 判定相同。** 细杆的检出靠 RGB（ToF 强档只有 0–22%）。已知问题：强光窄走廊中，扫把还在 3–4 m 外时就对墙面和吊牌报警。

## 3. 查清的机制

1. **方向合同错误**（10-11）：原始 zone 顺序与模型约定差 180°，已修复。
2. **训练噪声口径偏小 10 倍**（10-12）：补噪声、随机化俯角和地面后，真实空场强档首次安静。
3. **ToF 仿射锚定退化**：低头看地面时把地面算到头高，RGB 满屏误报（96%）。稳健拟合可修复，这就是 v3。
4. **标定失败的原因是强光**：弱光下哑光地面和反光地面都能标定，头高 1.32–1.34 m；下午阳光下 67–78% 的区报 0，标定失败。
5. **走廊误报不是尺度或标定问题**：地面锚定把地面放在头下 1.34 m（标定 1.35 m），是对的；误报像素是墙面和吊牌，被 DAV2 的相对深度形状算近，正好擦进盒子远角（深度中位约 1.9 m，横向约 +0.25 m）。误报和细杆检出走的都是地面锚定这条路。

## 4. 已排除的方向（都在已用数据上，保留失败记录）

| 方向 | 结果 |
|---|---|
| 多帧 RGB 投票（maj3/any3） | 没有修复任何失败段 |
| 6 种 ToF 区与视差的对应方式 | 锚定通过率 29.5–31.0%，没有提升 |
| 头高固定为实测 1.55 m（v4） | 误报降低，但一段扫把末段 1.00→0.47 |
| 头高 1.55 m＋IMU 俯角零点修正 −4.7°（v5） | 误报回升，扫把仍为 0.47 |
| 合成数据训练的学习式尺度 | 留出场景 9.3% vs 拟合链 7.9%；真实数据上空大厅报警 99%、扫把漏报 |
| 仅靠地面锚定的 RGB 不报警 | 误报清零，但丢掉 4 段真报警 |
| 像素团深度跨度 ≤0.5 m | 完全不起作用（墙面误报团同样紧凑） |
| SANPO 细杆诊断、OctoNet bin 映射 | 距离段不匹配 / bin 宽无法识别 |

## 5. 当前候选与下一步

- **ADT 独立检验（10-13 晚）**：13 段 5825 帧有真值的头戴数据上，v6 误报 7.74%→5.93%（相对 −23%），1.5 m 内检出 81.2%→80.6%，按预注册规则得到支持；代价是 1.5–2 m 处起报变晚。ToF 为模拟，见 [ADT 结果](ADT_EVAL_RESULT_20261013.md)。

- **v6（待冻结检验）**：v3＋像素团深度规则（RGB 报警像素团的深度中位须 ≤1.8 m）。冻结脚本在五批已用数据上：走廊开头误报 0.96/0.97 → 0.39/0.35，没有段由通过变为未通过，054159 末段 1.00 → 0.60（事后选择，需新录制检验）。已冻结，见 [v6 协议](FROZEN_FUSION_EVAL_V6_PROTOCOL.md)。
- **还需录制**：白天强光下的同一条窄走廊空通道 2–3 段，同时低头标定；更多细杆；录前确认 Atom 预览流畅。
- 尚未做：手机 App 接入 v3/v6；真实导航和听感验收。
