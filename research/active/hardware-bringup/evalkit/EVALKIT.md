# 近场避障评估协议（最小版本）

2026-11-17 起草，EXPLORE。这是“轻量评估协议”的最小实现：不采集新数据，用统一口径在已有公开数据上比较深度与尺度方法，
并在跑实验前拦下数据格式问题。按用户 11-17 的意见，定义不照搬 App 的相机相对盒子，而是按行走者的身体来定。

## 为什么要有它

11-16 至 11-17 的实验中，以下问题多次左右或推翻了结论：
- 误报按次数还是按帧数计；
- 真值怎么定义；
- 深度存的是光轴深度还是射线距离（Aria）；
- 位姿能不能当重力用（SANPO）。

本协议把这些固定下来，让所有方法在同一把尺子上比。

## 定义

| 项 | 定义 | 理由 |
| --- | --- | --- |
| 走廊 | 左右 ±0.35 m，前方 0.30–2.50 m，沿水平头朝向 | 半肩宽 0.25 m 加 0.10 m 余量；2.5 m 约为正常步速下反应加停步所需距离 |
| 高度带（离地） | 低 0.15–0.50 m（绊脚）、躯干 0.50–1.30 m、头部 1.30–2.00 m（悬挂物） | 头戴与胸戴可比；低矮物单列；v1 起下限 0.15 m，避免地面误差越线 |
| 有障碍 | 带内障碍物表面面积 ≥ 0.005 m²（约 5×10 cm）；面积为 0 算无障碍，介于两者之间算模糊、不计。v1 起先对带内掩码做 3×3 开运算，参考与预测同样处理 | 与距离无关，能覆盖细杆；开运算去掉立体深度的孤立飞点 |
| 地面与重力 | 评估端用参考深度以 RANSAC 拟合地面，法向须在设备重力 15° 以内（无设备重力时假设相机 y 向下） | 走廊和高度都相对真实地面 |
| 区域 | 近场 0.5–3 m；近场非地面（离地 > 0.15 m）；每个高度带的走廊 | 区分“地面上准”和“障碍物上准” |
| 深度指标 | 每帧 AbsRel 中位与 δ1（比值在 1/1.25–1.25 内的比例），先在块内取中位，再在块间取中位 | 块是独立性单位 |
| 检出指标 | 按帧的检出率（另按 0.3–1、1–2、2–2.5 m 分段）；按帧的误报率；误报“次数”（连续误报帧合并为一次）每分钟 | 次数与帧数并列，防止口径误导 |
| 方法比较（v1.1） | 两个方法只在**双方都有输出**的帧上配对比较；各自的“无输出帧数”单列；另报“无输出算不报警”的系统口径 | 某方法在难帧上缺席时，单看各自分母会偏向它（A1 SANPO 复核） |

## 接入前自检（不通过即不跑）

在每个数据集抽约 20 帧，检查以下各项：

| 检查 | 通过条件 |
| --- | --- |
| 单位 | 有效深度中位在 0.5–50 m |
| 深度含义 | 把文件当光轴深度时，最大平面的内点比例不低于“当作射线距离”时的结果（容差 0.02） |
| 平整 | 最大平面的内点比例 ≥ 0.4 |
| 传感器高度 | 头戴 1.2–1.9 m，胸戴 0.9–1.6 m |
| 重力 | 若有设备重力，与地面法向的夹角中位 ≤ 5° |

## 方法（`methods.py`）

| 方法 | 内容 |
| --- | --- |
| reference | 参考深度本身，作为健全性检查：误差应为 0，检出完美 |
| tof_dav2s | DAV2-S 加模拟共轴 45° 8×8 ToF 锚定（项目链：拟合，失败用稳健拟合，再失败沿用上一帧） |
| unidepth_s | UniDepth-V2-S 自带公制尺度，给定内参 |
| oracle_dav2s | DAV2-S 逐帧用参考深度仿射（形状上限） |
| tof_unidepth | UniDepth-V2-S 乘一个尺度（各 ToF 区“ToF 距离 / 模型距离”的中位）；区不足 5 个时沿用上一帧，从未有过尺度时用未校正输出（方向 A） |
| tof_dav2s_out / tof_unidepth_out | 同上，模拟户外受限 ToF：只留 ≤ 2.85 m 的区，每区乘 (1 + N(0, 3%)) |

运行：`python run_minimal.py <输出目录> [数据集 ...]`，输出 `report.json`、`report.md` 和逐帧 `rows_*.json`。

## 已知局限

- 参考深度都是立体伪真值。
- 模拟 ToF 理想、无噪声、与相机共轴。
- 头朝向走廊，尚未支持按行进方向画走廊。
- 块之间不完全独立（Aria 两段是同一路线）。

## v1 变更（2026-11-17）

依据是 v0 首次运行，以及只用参考深度的面积分布检查（Aria，601 帧，不涉及任何方法）：

1. **低矮带下限 0.10 → 0.15 m**，近场非地面阈值同步改为 0.15 m。v0 中形状上限在低矮带也有 27% 的帧误报。
2. **高度带掩码先做 3×3 开运算再计面积**，参考与预测同样处理。v0 的“模糊”帧面积中位只有约 1 cm²，是立体深度的孤立飞点。
   去掉后，模糊帧比例变化如下，“有障碍”比例几乎不变（0.06 / 0.38 / 0.38）：

   | 高度带 | 头部 | 低矮 | 躯干 |
   | --- | ---: | ---: | ---: |
   | 模糊帧比例 | 0.41 → 0.05 | 0.15 → 0.02 | 0.16 → 0.03 |

3. **SANPO 接入修正**：v0 对每个会话都取 `session_camera_details[0]`（胸前 ZED 2i）。
   v1 按 `session_camera_location` 选对应相机，头戴会话改用 ZED Mini 内参（fx 约 1368，原为 1974）。
   v0 自检拦下的“头戴高度约 1.16 m”正是这个错误造成的：1.16 × 1974/1368 ≈ 1.67 m。

这些修改发生在看过 v0 方法结果之后，属于协议修订，不是对某个方法的调参；v0 的输出保留在 `artifacts.local/work/evalkit-minimal-20261117/full`。
4. **严格负样本**（在第 2 条运行之后补充）：只在开运算之后判“空”，会把原本“只有零星飞点”的帧变成负样本。
   这些帧上方法看到成片表面就会被算作误报，但伪真值在那里可能只是没拍清细、暗、无纹理的物体。
   第 2 条单独运行时，tof_dav2s 的误报帧比例在低矮带从 0.10 升到 0.17，躯干带从 0.02 升到 0.10，结果保留在 `v1_opened_negatives/`。
   所以 v1 定为：
   - “有障碍”用开运算后的面积；
   - “无障碍”要求开运算前参考里**一个点都没有**，只有飞点的帧算模糊；
   - 报告中同时给出“开运算后为空”这一口径的误报率作对照。

   开运算因此只让正样本判定更稳；负样本的模糊帧回到 v0 水平。这是伪真值本身的局限，规则消不掉。

## v1.1 变更（2026-11-17）：配对比较

起因：[方向 A 的 SANPO 复核](../DIRECTION_A1_RECHECK_SANPO_20261117.md)。
- v1 的汇总按“各方法自己有输出的帧”计数。现做法在 SANPO 上有 483/1260 帧（可评分帧中）没有输出，
  比较的就不是同一批帧，而且缺席的正是最难的帧。
- 实验 1 里“本地 SANPO 上方向相反”就是这个原因造成的。

改动只增加输出，不改任何已有指标。用两份已存的逐帧结果核对过：未配对的汇总与原报告逐字段一致。
1. `summarize` 增加 `no_output`（可评分但该方法没有输出的帧数）和 `frames`，并可用 `keep` 限定帧。
2. 新增 `compare(rows, a, b)`：
   - 检出：每带只取双方都有输出的帧，给出双方的检出与误报计数，以及不一致对（只有 a 检出、只有 b 检出）与精确符号检验 p 值，正负样本各一份；
   - 深度：每个区域只取双方都有 AbsRel 的帧，先块内中位、再块间中位，并报告 b 更好的块数；
   - 系统口径：把“无输出”算作“不报警”，在全部可评分帧上计数。
3. 逐帧结果新增 `evaluable` 标记（评估端是否拟合到地面）。旧结果缺这个字段时，以“任一方法有输出”代替。
4. 命令行：`python paired_report.py <rows_*.json> <基线方法> <新方法> [输出 json]`。

**写判据的规则（v1.1 起）**
- 方法之间的比较，主判定用 `compare` 的配对结果；无输出帧数和系统口径同时报告。
- 检出容差用帧数（或不一致对数）写，并先按预计阳性数换算：容差不足 3 帧时，该项预先记为不可分辨，不进入判定。
  反例：A1 复核中 0.02 × 58 个阳性 ≈ 1.2 帧，一帧之差就决定了判定。
- p 值只作描述，不替代预先写定的阈值。

## v1.2 变更（2026-11-18）：按障碍物计分

起因：[ADT 室内追查](../DIRECTION_A_INDOOR_ADT_DEV_20261118.md#追查室内低矮带为什么变差1118开发)。
- 按带计分时，同一个跨带障碍物（例如较高家具的下部）被深度误差抬进躯干带，就会记成“低矮漏检”，尽管躯干带已经报警。
- ADT 上新链低矮少检 42 帧，但按任一带看，检出两者相同（1913 对 1913）。

改动只增加输出，不改任何已有指标（`core.compare` 的 `detect` 与深度部分不变）。
1. `compare` 新增 `obstacle`，口径与按带的配对结果相同（共同输出帧、双方计数、不一致对与精确符号检验、系统口径），报警一律取“任一带报警”：
   - **ANY**：任一带有障碍物为阳性；三带都严格为空为阴性；其余不计。
   - **LOW_ONLY**：低矮带有障碍物且躯干带严格为空为阳性（脚边、躯干高度没有东西，盲杖最该补的情况）；阴性同 ANY。
2. `paired_report.py` 同时打印两种口径；`PROTOCOL_VERSION` 改为 v1.2。

**写判据的规则（v1.2 起）**
- 按障碍物（ANY）的检出与误报，同按带的结果并列报告。
- 用哪一种口径做主判定，要在运行前写定。默认仍用按带的低矮、躯干两带，按障碍物作为必须报告的辅助口径。
- LOW_ONLY 阳性通常很少（下表 9–28 帧），只作描述，除非预计阳性 ≥ 30。
