# 实机输入合同 v5：zone 方向、近距串扰拖尾与直流基线

2026-10-11 · EXPLORE · 执行者 Claude（用户授权“你来做”）。复用已消费的宿舍十段 pilot（772878a5，1507 帧），冻结模型、阈值、默认候选均不改。

## 结论

**此前所有实机回放的模型输入上下颠倒。** 冻结投影器 `cnh_cvr_projection.Projector` 与模拟器 `angular_rays` 都约定 zone 行 0 在上（Y 向下）、列 0 在左；当前头戴 XIAO/L8CH 的原始输出是行 0 在下、列 0 在右（接收镜头翻转画面，ST UM3183 §2.2）。`m3_live_engine`、`real_pilot_calibration` 系列与 `local_signed_bias_*` 回放都直接 `reshape(8,8,16)` 送入模型。这解释了竖杆只报 HEAD、台架演示 HEAD 248/248 而 BODY 0 等现象。

方向证据：
- `installation-view.json` 记录 `raw_to_current_display: row=7-raw_row,col=7-raw_col`，已对照用户上/右定点截图（显示网格左上为 zone 63，上方定点时顶部几行出现 19–25cm 近回波）；
- 宿舍横杆段原始第 0 列在 0.6–1.2m 处全部 8 行都有强回波（t 39–118），只能是侧面的竖直结构（过道右侧床梯），地面在 1.55m 高度不可能出现在这个距离，因此行为竖直方向、原始列 0 为右；
- 上下方向不依赖相机镜像设置；左右方向另有床梯证据，但仍以安装记录为准。

另外两个只存在于真实数据的问题：
- **近距串扰拖尾**：bin0（0–0.30m）在所有条件下约为 57–63，与环境光无关，重启后约 +10%，是内部串扰。它拖尾到 bin1 约 2%、bin2 约 0.6–0.9%、bin3 约 0.3–0.6%。v2/v4 模板主要取自阳台（环境光约 474，bin1 仅约 0.5%），室内拖尾因此被低估约 4 倍。0.3–1.2m 在视场内只覆盖光轴上下约 0.25m，只落入 HEAD 走廊，所以表现为 HEAD 假报警。
- **随环境光变化的直流基线**：无目标 bin 的均值，室内为 +0.14 到 +0.23，强光下为 −2.3。暗档噪声底小，正偏置被放大后在投影中累积，导致 4b 全报警。

v5 下 M3 网络本身在空通道 4/4b/9 均为 0/0，残留强报警全部来自原5格中的解析 LOCAL 分支（old5 = raised M3 OR LOCAL）。消融显示：空通道残留由 0.9–2.7m（主要是 bin3 拖尾残差，平均 z 约 0.2–0.3）驱动；外侧杆的 BODY 来自 3m 以外的尽头墙（窗口边界场景）；横杆由 0.9–2.7m 的杆本身驱动；2m 远杆在其距离段平均 z 为负，看不到（与细杆能力边界一致）。去掉 bin1–2 再加方向和基线的探索变体中，空9 为 0/1、近杆 0/40、空4 仍 97/0（LOCAL）。

拖尾比例按留一段法从无近物的室内段（3、4、4b、9）估计。逐 zone 比例图在段间相关性只有 0.05–0.59，真实侧标定扣不干净，LOCAL 对这种残差极敏感。因此剩余问题需要在模型侧解决：模拟器域随机化加入串扰拖尾与直流基线，LOCAL 在随机化噪声下重新校准或替换。

## 局限

全部为已消费 pilot 上的开发描述；三项修正都是看过这批数据后才发现的，不是独立确认。头戴俯角未知、尽头窗帘约在 3m 窗口边缘、近/远杆旁有筒，空通道不是干净的 clear。不报告实机检出率或误报率。
