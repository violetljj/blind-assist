# 贴近用途的评价口径与“走/停”报警距离（规则未过，但不必要报警减半）

2026-10-14，EXPLORE，执行者 Claude。数据为 Aria Digital Twin Dataset（Meta Reality Labs Research）；判定规则在计算前写入 `artifacts.local/work/adt-eval-20261013/PLAN_TASK_METRIC.md`。直接读取角度扫描已存的每帧像素团（DAV2-S 锚定链，[ADT_TOF_AIM_BACKBONE_DEV_20261013](ADT_TOF_AIM_BACKBONE_DEV_20261013.md) 第 5 节），只用 CPU，几秒钟。

## 口径

原口径把“盒内 2 m 以内有任何东西”都算作该报警，站着不动时 1.5 m 外的桌子也算。新口径按 GT 水平速度 v 定义：

- **威胁**：盒内 ≥150 GT 像素，且中位深度 ≤ 0.5 m + 2 s × v（静止 v < 0.3 m/s 时为 0.7 m）；
- **空盒**：盒内 0 像素；
- **不必要**：盒内有东西但不构成威胁。

规则：v6 不变（像素团中位深度 ≤1.8 m 才计）；v6s 把上限改为 clip(0.8 + 2v, 0.8, 1.8) m，v 用 GT 速度；v6w 同上，但只区分走（按 1 m/s）和停（0），这是 IMU 步频检测就能提供的信息。ToF 报警不变。

## 结果（query 帧，2/3 确认；现安装角 = i0 / d0，下倾 30° = i30 / d30）

| 条件 / 规则 | RGB：威胁检出（其中走路时） | RGB：空盒误报（站着 / 走路） | RGB：不必要报警 | 融合：威胁检出 / 空盒误报 / 不必要报警 |
|---|---|---|---|---|
| i0 v6 | 78.7%（73.2%） | 5.9%（6.0 / 5.9） | 77.0% | 83.3 / 6.7 / 86.9% |
| i0 v6s | 77.7%（72.8%） | 4.8%（3.9 / 5.3） | 51.6% | 82.9 / 5.8 / 74.4% |
| i0 v6w | 76.9%（72.1%） | 4.8%（3.5 / 5.4） | **43.2%** | 82.5 / 5.8 / 69.7% |
| d0 v6 → v6w | 76.6 → 74.1% | 9.1 → 7.1% | 80.2 → 45.6% | 81.8 → 79.8 / 9.8 → 8.0 / 86.9 → 67.3% |
| i30 v6 → v6w | 86.7 → 85.3% | 5.7 → 4.2% | 80.9 → 43.6% | 93.0 → 92.7 / 6.8 → 5.5 / 87.9 → 81.0% |
| d30 v6 → v6w | 88.0 → 86.7% | 6.8 → 5.2% | 82.1 → 45.4% | 93.0 → 92.8 / 8.1 → 6.8 / 88.1 → 81.4% |

i0 的分母：威胁 6167（其中走路 3269），空盒 2831（其中站着 985），不必要 1516。

**判定**：预先规则要求 v6w 在 i0 上空盒误报 ≤0.75 倍、威胁检出降幅 ≤2 个点。实际误报是 0.81 倍、检出 −1.8 个点，**不达标**。

但在同样预先列出的“不必要报警”上，四种条件都从约 80% 降到约 45%，威胁检出只降 1–2.5 个点。也就是说，主要收益不在空盒误报，而是**站着时不再对 1–1.8 m 的东西报警**。v6w 和用精确速度的 v6s 差不多，所以只要能判断“走还是停”就够了。

## 其他发现

- 新口径下的弱项：走路时的威胁检出只有 72–73%（现安装角，RGB）；融合 ToF 后约 83%，下倾 30° 后约 93%。
- 融合后的不必要报警只降到约 70%，因为 ToF 报警没有按距离收紧（扫描时只存了每个盒子是否报警，没有存距离），这还有空间。

## 追加：ToF 也按走/停收紧（v7w，判定写入 `PLAN_TASK_METRIC_TOF.md`）

不重跑模型，只用真值重新模拟 ToF，并记录报警距离（每个报警区盒内回波深度的中位数，取各区最小值）。报警标志与角度扫描逐帧一致（23300/23300），4 个进程用时 14 s。v7w = v6w + ToF 报警距离也要 ≤ 上限（走 1.8 m、停 0.8 m）。

| 融合：威胁检出 / 空盒误报 / 不必要报警 | v6 | v6w | v7w |
|---|---|---|---|
| 现安装角 理想 i0 | 83.3 / 6.7 / 86.9% | 82.5 / 5.8 / 69.7% | 80.5 / 5.1 / **49.0%** |
| 现安装角 打折 d0 | 81.8 / 9.8 / 86.9% | 79.8 / 8.0 / 67.3% | 77.3 / 7.3 / 49.6% |
| 下倾 30° 理想 i30 | 93.0 / 6.8 / 87.9% | 92.7 / 5.5 / 81.0% | 91.8 / 5.2 / 52.9% |
| 下倾 30° 打折 d30 | 93.0 / 8.1 / 88.1% | 92.8 / 6.8 / 81.4% | 92.0 / 6.1 / 53.6% |

**判定**：预先规则要求在 i0 上不必要报警 ≤0.6 倍、威胁检出降幅 ≤2 个点、空盒误报不升。实际不必要报警 0.56 倍、误报 6.7 → 5.1%，都满足；但威胁检出 −2.8 个点，**差 0.8 个点，不达标**。下倾 30° 时检出只降 1.2 个点，不必要报警 0.602 倍，正好卡在线上。

解读：ToF 一起收紧后，融合系统的不必要报警从约 87% 降到约 50%，代价是现安装角下 2–4.5 个点的威胁检出。下倾后代价更小，因为下倾的 ToF 本身看到的就是近处。这个规则适合作为下次冻结的候选 v7，与 v6 一起在真实录制上比较，不宜在没有新数据的情况下直接替换 v6。

## 自录数据诊断（已用数据，冻结标签，IMU 步频判断走/停）

10 个有判定的段，结果没有变化（通过 / 不通过都一样）。走廊扫把段的任一报警率 0.37 → 0.30，侧杆段 0.13 → 0.00。自录段大多在走动（走动比例 0.4–1.0），所以规则起作用的机会少。唯一一段最后停下来的（扫把在白墙前约 1 m），末段由 ToF 强档保持报警。

## 边界

- 威胁的定义（2 s 反应时间、0.5 m 余量、静止 0.7 m）是我们定的，不是标准；换参数，数字会变。这里只证明了方向。
- ADT 是做家务的场景，静止和慢走比盲人出行时多。
