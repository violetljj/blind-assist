# 手机热点优先与采集页排版：2026-10-13

用户要求两块硬件优先连接已配置的手机热点，随后要求实时预览与开始／停止相邻。原固件保持现有 Wi-Fi，手机关闭 Wi-Fi 后两板仍留在路由器；本轮修改共享网络层与采集页布局，不运行模型、训练或冻结评价。

## 行为

- 槽位 1 是手机热点，槽位 0 是原 Wi-Fi。开机、断线和 USB 重连先尝试热点，每次连接最多 12 秒，再回退原 Wi-Fi。
- 连着原 Wi-Fi 时每 30 秒异步、按已配置热点名称检查；发现热点便迁移。热点可见但连接失败后回退，并等待 120 秒再检查。
- 热点关闭后回退原 Wi-Fi；重开热点后再次迁移。扫描上限 5 秒，取消扫描后才开始连接；现有网络凭据、传感器数据格式和配置保留。
- 切网会结束正在采集的 TCP 段，保留中断记录；两板接入后在 App 点击“自动寻找设备”，再开始新段。

## 验证与交付

共享固件实际 C++ 头的 host mocks 已通过，覆盖热点优先启动、热点不可用回退、原 Wi-Fi 上自动迁移、热点掉线、迁移失败冷却、扫描失败/取消/超时、旧配置迁移与凭据不输出。该检查是模拟状态机证据。

两板更新前 app 已从设备读回，与此前构建文件 SHA256 一致。两个真实固件构建通过，只写 app0 `0x10000` 并通过 esptool hash 核验；原 NVS、网络配置和分区保留。

- 手机 Wi-Fi 关闭、热点开启时，两板状态均为 `hotspot_first / profile_index=1`，Atom 为 `10.238.31.218`，ToF 为 `10.238.31.236`。
- 在产品采集页自动寻找、开始及停止，41.404 秒工程段保存 626 RGB、130 有效 CNH、4140 有效 IMU，`COMPLETED/user_stop`。626 图像已有 bytes/hash、CNH 原字节覆盖/8×8×16 和 IMU 引用检查通过；有 1 个 CNH 缺 100 ms 内 RGB 接收匹配，如实保留。该工程段 `capture-20261013T063141690Z-d18cc51a` 不纳入冻结评价。
