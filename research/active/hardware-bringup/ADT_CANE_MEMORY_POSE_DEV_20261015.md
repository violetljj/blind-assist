# 地面记忆的位姿误差敏感性与台面悬挑漏检（2026-10-15，EXPLORE）

执行者 Claude。承接 [短时地面记忆](ADT_CANE_MEMORY_DEV_20261015.md)：上一轮用的是 GT 位姿，真机只有陀螺/重力给出的旋转，平移只能靠步行推算（PDR）。数据为 Aria Digital Twin（Meta Reality Labs Research，非商业研究），只报告汇总。计划与判定在运行前写入 `artifacts.local/work/adt-eval-20261013/PLAN_POSE_ERR.md`。

## 做法

所有臂都用设备自己的锚定 DAV2 深度（chain），估计器、标签（`cane_reach_v3.json`）和分层与上一轮完全相同，只改融合过去 3 s 地面点时用的位姿：

| 臂 | 位姿 |
| --- | --- |
| A0 | GT（复现基线） |
| S± | 方向为 GT，步长 ×1.2 / ×0.8 |
| H | 步长为 GT，方向取当前头部朝向（PDR 看不到真实行进方向） |
| HS± | H 再叠加步长 ×1.2 / ×0.8 |
| Z | 不估平移，只有旋转（下界） |
| P± | GT 平移，相机俯仰常值偏差 ±3° |

竖直位移一律沿用 GT。判定：HS 两臂中较差者，冗余压缩比例 ≥ A0 的 80%，且近距漏检检出 ≥ A0 − 2，即判"PDR 级位姿足够"。

## 判读

1. **按预注册判定，PDR 级位姿足够**：最差的 HS+ 冗余压缩 84.6%（≥ A0 的 80%），漏检检出 29/38，恰好落在下限 31−2 上。步长 ±20%、俯仰 ±3° 的影响都在 1–2 个漏检帧以内。
2. **平移必须估**：只有旋转时，冗余压缩从 80% 掉到 52%，因为记忆里的地面点没有随人前移，进不了脚前的盲杖带。真机需要步数 × 步长，方向用头部朝向即可。在这批 ADT 行走段上，用头部朝向代替行进方向反而多压了一些冗余，代价是 2 个漏检帧。
3. 误差的代价总在同一处：凡是让记忆"多找到支撑"的误差（步长偏大、头部方向、俯仰向下），冗余压得更多，漏检也丢得更多。

## 台面悬挑拆解

A0 误压的 4 个近距漏检帧都来自**同一件物体**：meal_seq131 中下面有开放隔层的中岛/桌子（两次经过）。对照 GT 深度与设备深度可见，设备深度把桌面下的空当画成从桌沿一直连到地面的实面，桌沿正下方于是出现"盲杖带内的支撑"；同时桌沿距离被估远了 0.2–0.4 m（GT 0.55–0.66 m，设备 0.84–1.06 m），搜索范围更大。

把 38 个近距漏检帧按近缘点高度粗分：台面类（顶 ≤1.15 m）18 帧，v6 检出 16，记忆后保留 14；高处类（搁板等）20 帧，v6 检出 19，保留 17。实际的独立物体只有约 6 个，误压全部集中在那一张桌子上。

**含义**：单目深度会"填平"悬挑下的空当，这是地面记忆误压真正危险的主要机制。和 ARKitScenes 中"细椅腿看不见"恰好相反：那边是漏掉真支撑，这里是凭空造出假支撑。可能的对策：支撑点要求在多帧、多视角中都与物体下沿有可见间隔，或者只采用在物体进入近距前就已观测到的地面点。两者都没有检验。

## 边界

一套公寓，漏检帧 38 个、物体约 6 个；PDR 误差用简单模型代替（步长取 GT 大小，没有模拟漏步、转身和竖直误差）；ToF 为模拟；真机还需要 Atom IMU 的步数检测与俯仰零点（已知约 −4.7°）。不代表真实佩戴效果。
