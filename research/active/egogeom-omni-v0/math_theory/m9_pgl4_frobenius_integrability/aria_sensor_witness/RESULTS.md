# Aria 两次行走有没有可用的独立障碍点？

本地正式下载包没有 MPS 半稠密点、逐帧点观测、原始双目数据或独立测距通道。最接近的替代是从当前及历史整流灰图重新匹配角点，用公制位姿直接三角化。它在固定走廊中找到少量障碍证据，但未通过清路预算。两次行走分别留出后的告警都是 0/143；这个结果限制本读出，不能证明带点云或物理测距设备也无效。

## 来源、配准与因果边界

逐项检查了下载收据列出的六个 ZIP 的中央目录。每个 walk 有三包。校准 ZIP 各只有一个 `online_calibration.jsonl`；轨迹 ZIP 各只有 `open_loop_trajectory.csv` 和 `closed_loop_trajectory.csv`；深度 ZIP 各含相同数量的整流灰图和 FoundationStereo 深度图，walk_0 每种 8,983 张，walk_1 每种 9,018 张，另有每帧针孔参数与计数。逐帧参数包含相机位姿、时间和内参，校准列出物理相机、IMU 及外参；这些描述都不提供实际场景中的表面点/像素观测。范围是本机这两次行走的项目下载包及对应缓存。官方另行发布的点包及其成本见末节。两名佩戴者走的是同一条路线，留 walk 不代表留地点。

推理单独执行。每段在 5 Hz 的已有 150 个时间戳上读取原始整流灰图，重置历史缓存；逐帧核对打包位姿与原始相机记录。先于评分保存 19 份不可变预测。预测代码未打开任何深度 PNG、未读 `eval_rows`、网络深度或目标标签。两版本均调用既有 M2 的双向 LK、正深度和视差角 ≥1.4° 的两视图检查；使用真实逐帧内参、256×256 图像和最近 10 帧内接近 0.32 m 的基线。匹配残差小不保证物体静止或两帧确实是同一点；不会自动恢复透明、无纹理、被遮挡物。

- **提供的相机位姿版本**采用每帧提供的重力对齐公制相机位姿，包括 MPS 离线精修的影响。图像和走廊航向只读当前及过去。
- **开环版本**使用不晚于曝光的 MPS 开环设备位姿。每个 walk 的第一帧，通过提供的相机位姿与同时刻闭环设备位姿确定一个固定整流相机外参；此后不再使用闭环位姿更新该臂。该外参基于离线产品，整条链未作实时验证。与后续闭环相机记录比较，固定外参角误差 P95 为 0.238° / 0.388°，平移差 P95 为 0.64 / 0.71 mm。其余有效帧的开环设备行与曝光时间精确对齐；walk_0 最初三帧欠缺可信开环位姿，输出未知。开环本地轨迹仍是上游重建产品；不给它赋予真机延迟或完全实时精度保证。

预设走廊横向 ±0.30 m、前向 0.30–4.00 m、名义固定眼高 1.55 m、离地高 0.15–1.9 m。行进方向用最近最多两步位移；不足 0.15 m 时用水平光轴。候选点按 5 cm 三维体素去重，以 30 cm 前向区间内的最大体素数为强度。固定读出要求至少三体素。为区分未见与清路，在 0.5–3.5 m 的七个截面上，每个截面的三横向×两高度格都须有至少一条延伸到该截面之后 0.3 m 的观测射线，才能赋予清路代理状态；这只是离散证据，不能证明截面内没有细障。两臂均无一帧满足全部 42 格。只有无回波时保持未知。

## 交叉验证与代价

2,850 帧，参照判有效危险 840、有效清路 954、参照未知 1,056。冻结 M3 六种步速计 143 个可及时告警组合，总行程 2.142183 walker-km。下表中的三元组依次为输出危险、清路代理和未知。

|---|---:|---:|---:|---:|---:|---:|
| 提供位姿，固定三体素 | 76 / 0 / 764 | 9 / 0 / 945 | 34 / 0 / 1,022 | 11/143 | 11.20 | 16.81 |

| 各自使用另一 walk 学得的双预算切点（两臂相同） | 0 / 0 / 840 | 0 / 0 / 954 | 0 / 0 / 1,056 | 0/143 | 0 | 0 |

每个训练 walk 只枚举该 walk 出现过的正体素数及关闭。在原 FA 和清路重复均 ≤5/km 的可行切点中，先最大化及时次数，再最小化重复、清路帧与总提示，最后选较高切点。两个训练 walk 各自都没有任何可行且有及时命中的切点。因此留 walk_0 得 0/104，留 walk_1 得 0/39，不能用事后跨走改阈值。对事先由 M9 评估定义的 13 个当时射线不足组合，固定与留走策略在其及时危险帧均为 0/13。

开环臂在 walk_0 / walk_1 各 825/1,350 与 990/1,500 帧取得任意有效三角化，共 21,823 / 25,397 个点；其中能在当前走廊产生至少一个候选的帧仅 149 / 224。提供位姿的同口径分别为 831 / 995 帧、22,128 / 25,294 个点、172 / 235 个走廊候选帧。开环单线程匹配和读出耗时 P50/P95 分别为 3.91/6.06 与 4.12/6.15 ms，排除了 PNG 解码、缩放、磁盘 I/O 和上游 VIO。两种位姿都存在稀疏结构遗漏和纹理选择偏差。没有独立的稠密地图或物理传感器覆盖，本轮只能裁决该直接三角化对照。

运行 [replay.py](replay.py) 后再运行 [score.py](score.py)。工件位于项目 `artifacts.local/work/egogeom-omni-v0/math_theory/m9_pgl4_frobenius_integrability/aria_sensor_witness/`；`observation_inventory.json` 记录 ZIP 成员、输入帧内容散列、时钟与固定外参核验，`sensor_witness.json` 记录每臂逐 walk 分母、训练切点及费用。

## 官方发布包和实际获取成本（2026-11-25）

官方 Dataset Explorer 为两名佩戴者分别列出 `mps_slam_points` ZIP。walk_0 为 **6.3 GB**，walk_1 为 **6.4 GB**，合计约 **12.7 GB**，是页面显示的十进制舍入值。两页各有 30 秒 Rerun 预览链接，完整下载清单没有列出共享的小型点与观测子包。此前本地下载收据仅保存所选六包及其校验值。本次范围约 100 MB，完整 ZIP 超出范围；单个点表的压缩尺寸须另查 ZIP 中央目录。[walk_0 发布清单](https://explorer.projectaria.com/gen2pilot/walk_0) · [walk_1 发布清单](https://explorer.projectaria.com/gen2pilot/walk_1)

要核查特定时刻的走廊障碍，至少需要 `semidense_points.csv.gz` 的地图内 `uid`、`graph_uid`、世界点坐标与 `inv_dist_std`、`dist_std`，还需 `semidense_observations.csv.gz` 的同一 `uid`、`camera_serial`、`frame_tracking_timestamp_us` 和像素 `(u,v)`。先核对地图坐标与该序列闭环轨迹的 `graph_uid`，再以相机和曝光时刻查观测、经标定投到实际像素并检查遮挡及走廊格。跨佩戴者的设备时间对齐本身不能证明地图、点 UID 和可见性共享。官方给出的名义不确定度上限为 0.005 m⁻¹ 与 0.01 m，点坐标来自离线重建；这些高梯度区的视觉轨迹与 FoundationStereo 使用不同估计算法，仍受共同成像、纹理与遮挡条件影响。点存在只能作离线几何互证，缺少点观测应记为未知。[MPS 点与观测字段](https://facebookresearch.github.io/projectaria_tools/gen2/technical-specs/mps/data_formats/slam/mps_pointcloud) · [Pilot 数据格式](https://facebookresearch.github.io/projectaria_tools/gen2/research-tools/dataset/pilot/format)

对“地图上是否共位”的较弱问题，仅取点表、使用公用的闭环地图坐标即可开展；未关联当帧观测时无法判定当时可见。HTTP 字节范围读取 ZIP 中央目录可先核实所需成员的压缩长度，只有成功提取完整成员后才能校验 CRC。本地项目收据明确未保存签名 URL，核查项目下载目录及系统下载目录亦未找到当时的下载索引。公开序列清单给出按钮和整包大小；官方指南将许可证与使用条款的接受列为下载步骤。此次未取得可直接 Range 读取的已授权点包 URL，因此**点表的单成员字节数、两包点表是否相同、Range 支持和 CRC 都未验证**。12.7 GB 只能作为两个整包的公布成本，不能作为仅点表的下载量。没有下载 MPS 成员，也没有测得原最近目标格与 MPS 点的共位率。[Gen 2 Pilot 下载指南](https://facebookresearch.github.io/projectaria_tools/gen2/research-tools/dataset/pilot/download)
