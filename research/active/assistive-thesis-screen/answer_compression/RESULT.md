# 语音回答压缩：实际小试不支持优先立题

2026-10-15，EXPLORE。把研究范围拓宽到信息呈现：在有限语音长度内，
能否同时保留答案、无法回答的说明和下一步建议？本轮结论是**可自动跑通，
但目前弱方法没有一致收益，数据标注还需要核对，优先级低于视觉任务**。

## 数据与方法

[LFVQA 作者数据](https://github.com/UT-CS-HCI/lfvqa)，固定 revision
`358d12904635bbf612558da10febfe5e35967540`，600 张不同图像/问题，
4,196 条专家与六类模型历史回答。原始 JSON 4,607,610 bytes；再次从固定
revision 读取，SHA256 与首次 main 下载一致，累计下载 9,215,220 bytes。

348/4,196（8.29%）条回答的句子与逐句功能标签数量不一致，全部排除，
没有截断标签或猜测修复；保留 3,848 条。即使长度一致也可能有语义标签噪声，
本轮没有人工重标。各生成器的不一致数量留在原始错误清单。

按图像 URL 的 SHA256 模 5 留出，488 张图像/3,116 条回答训练，
112 张图像/732 条回答评价。同图像的所有模型回答都在同一侧。
只用句子文本的 unigram/bigram 训练三个二元朴素贝叶斯功能分类器，
按预测的答案、失败说明、建议覆盖率贪心选最多两句。推理不读取真实角色、
可回答性、图像身份或生成器名称。对照是直接取前两句。

## 实际结果

主要看真正会被压缩的 150 条三句以上留出回答；两臂都选 300 句。

| 已标注角色覆盖 | 前两句 | 学习选两句 | 变化 |
| --- | ---: | ---: | ---: |
| 答案（123 条原回答含该角色） | 99/123 | 99/123 | 0 条 |
| 无法回答说明（53 条含该角色） | 35/53 | 33/53 | -2 条 |
| 建议（49 条含该角色） | 29/49 | 33/49 | +4 条 |
| 原有三类角色全部保留（149 条含至少一种） | 93/149 | 96/149 | +3 条 |
| 选出英文词数 | 5,041 | 4,751 | -290 词 |

全部 732 条结果：答案 585/609 → 585/609，失败说明 117/135 → 115/135，
建议 53/73 → 57/73。大量单句或两句回答没有压缩机会，因此以上 150 条机会集
更适合解释机制，但不能冒充另外的独立数据集。

## 判断与下一步

不能把多保留建议、少保留失败说明说成全面改善。功能标签不等于答案正确、
建议可执行或视障用户偏好；相同句数也不等于相同词数和语音时长。
这是已有回答的标注回放，没有运行 VLM、生成新回答或测量用户体验。
现代强摘要/回答模型 **NOT_RUN**，不据此宣称领先。

若后续继续，两个方法章节可分别研究：问题条件下的证据与必要信息识别，
以及保留不确定性表达的自适应语音压缩。最弱假设是这些功能标签能可靠对应
用户真正需要保留的信息。先核对标签对齐、建立等词数的强摘要对照，
再决定是否值得投入；当前不优先。
