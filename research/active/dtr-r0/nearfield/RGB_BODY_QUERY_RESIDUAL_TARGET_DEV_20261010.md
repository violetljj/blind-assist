# RGB：train/cal 有界 log-Z 目标与输入兼容性诊断

日期：2026-10-10。`RGB_BODY_QUERY_RESIDUAL_TARGET_DEV_20261010`，EXPLORE，已消费 Development。前轮见[输入与数值诊断](RGB_BODY_QUERY_INPUT_NUMERICS_DEV_20261010.md)，原 A0 全 δ/三 capture 见[A0](RGB_BODY_QUERY_A0_DEV_20261010.md)。

## 结果与决定

旧 ±0.2 对近带目标太小；但扩大界限也没有解决迁移。按预声明规则得到的 train/cal q99 envelope 为 **±3.184721 log-Z**，虽覆盖 pooled cal 99%，仍仅容纳 ARKit cal 近带 **74.958%** 的所需修正。它对应每方向约 **24.16 倍**深度变化，是宽界限，不能称为强约束或采用理由。

固定 depth/ray 邻域代理在 ARKit cal 近带把 MAE 从 **1.9614 降到 0.8289**，但追加 3RScan 近带 **0.6008→0.6104**；原 train 留一环境整体 **0.3171→0.4193**。三组 ARKit cal 访问整体均改善，train 7/7、原 cal 2/2、追加 3RScan 15/15 环境整体均变差。收益与损失一并保留；这支持继续检验修正机制，却不支持直接照搬旧三项输入的局部迁移或仅扩大 bound。

保留全局 log-affine 作为当前 RGB 代表。下一实际训练优先检验**有界 log-Z 残差＋可观测局部深度上下文**，以 depth/ray 三项输入残差作同预算对照；先从缓存原生 DP 的局部梯度与多尺度邻域统计增加信息。无需把本轮兼容性诊断再变成训练前置门槛。具体模型/预算在训练 run 中冻结；本轮没有训练，也不据此提升为查询收益结论。真正训练的残差、RGB 上下文以及其他校准方法均未被否定。

## 冻结输入、目标与口径

只用原 train **56 帧 / 7 环境 / 1,591,791 有效原生点**，以及原 cal16＋追加 3RScan240＋追加 ARKit48，即 **304 cal 帧 / 20 环境标签 / 9,853,778 有效点**。train/cal 帧和环境标签分离，新增 cal 未改作 train；三次 ARKit 访问也不等于三个独立硬件/相机域。共 360 帧、11,445,569 有效点，未访问 136 帧 evaluation cohort。

冻结主干：`log z_affine = 0.3713312368564329 log z_DP + 0.2635894826641125`。目标 `r = log z_native_first_return_reference − log z_affine`，掩码与旧 train 的有限正 DP / 有限正参考一致。它是原生 first-return 距离目标，不是 whole-body/query label。参考仅用于监督目标和评价。

读取参考像素前，对每帧 public finite-positive DP 原生索引按 rounded-linspace 固定 512 点。360×512＝**184,320** 输入样本全部取邻居；其中 **145,353** 有有效参考，**38,967** 缺参考，不补点。公开采样不使用 GT、来源标签、距离带或 query 标签。

输入只有 `logDP, ray_x, ray_y`，mean/std 只由原 train 得出；bank 为全部 1,591,791 train 点。固定标准化欧氏距离、k=16、邻居残差中位数，不拟合参数。train 查询排除整个同环境（7 折 LOEO）；cal 只查 train bank。cal 目标从未进入 bank。GT 距离带只在完成公开采样后作描述，半开区间 `[0.3,0.8)` 等，不是查询协议的闭区间。输入邻距是无量纲标准化距离，不是米。

四条规则在查看结果前固定：旧 δ=0.2、train |r| q95、train |r| q99、max(train q99, pooled cal q99)。主候选为最后一条；没有逐环境挑最佳、重选 k、按 eval 倒推 bound 或默认输入范围回退。

## 下一训练设计（未执行）

沿用 `log z = log z_affine + B tanh(h_theta/B)`，输出层零初始化，使初始输出等于 affine；B 的现有候选是预声明 envelope 3.184721，保持 train/cal 来源且不据 eval 修改。这个候选允许大修正但不保证稳定，也不能覆盖全部 ARKit 近带。训练 run 应明确它是待验证设计，不把 pooled 99% 容量当升级门槛。

首选增加缓存 DP 局部梯度和多尺度邻域统计，与只含 logDP/ray 的同容量臂比较；仅可观测输入，不引入 GT距离带、capture ID 或 query真值。弱假设是局部空间上下文能解释当前三项输入遗漏的修正；它可能仍无法弥补 train 环境覆盖和原始 DP 错误。用原 train 监督 log-Z first-return residual、保留完整残差目标（不把超界标签静默删除），环境/帧权重和损失在新训练 run 中固定；cal 保留校准角色。训练后的完整查询级救/损、近带与实际 FREE 成本才回答收益问题。

原共识双判据继续作为双方认可的强信号：Claude视为必要门槛，Codex视为充分条件；未满足不自动为负，明显增加正见证且成本小幅增加仍展示代价供权衡。本轮没有查询工作点比较，不能判定双判据。
